# AI辅助使用说明

## 如实披露

本项目由候选人与Codex协作完成。本轮对话中，候选人提供了完整考题，选择企业知识问答方向，并要求新建独立文件夹实现可提交项目。不能把以下AI完成的工作描述成候选人独立编写或独立验证。

AI辅助范围：需求拆解、架构设计、合成资料、提示词、Python实现、离线模型替身、自动化测试、真实模型调用、Trace整理、代码检查和文档初稿。AI也负责发现并修复首轮检索误召回问题。程序运行时的QA模型与开发辅助AI是两个不同角色，实际QA模型名记录在每次运行文件内。

开发环境中只读参考了已有project2的RAG入口和模型接入配置，发现其固定检索流程不适合作为本题直接交付。本项目代码重新编写，没有复制其业务库、前端、账号或运行数据。使用现有本地配置进行合成数据的真实模型验收，实际密钥未复制到此仓库。

## 候选人贡献与尚未完成的个人工作

可确认的候选人贡献：提供题目与约束、选择方向、决定独立项目交付、提供目标GitHub仓库并完成发布认证。当前记录没有证据证明候选人逐行修改了代码或亲自完成以下复核，因此不替其填写此类声明。

提交前建议候选人实际完成并据实补充：

1. 运行README中的命令，核对本机结果。
2. 阅读agent.py、models.py、validation.py，解释模型决策与程序约束的职责。
3. 对照原文复核正常、冲突、资料外、上下文与故障回答。
4. 自行修改一份资料，确认输出改变，记录命令和结果。
5. 若有个人代码修改，填写具体文件、修改目的和验证证据；若没有，明确写没有。

上述为待本人完成事项，不表示已经完成。项目内由AI执行的自动检查、实际模型Trace和AI审阅记录均按其真实来源标注。

## 验证来源

- unittest结果由真实执行生成，不由AI手填通过日志。
- Mock验收仅验证流程和工程约束，不证明真实模型决策能力。
- live记录由外部模型实际返回的结构化动作驱动；失败和成功分别保存，不把失败结果替换成模拟答案。
- 自动语义断言限于固定合成样本的关键词、状态和来源检查；AI逐条审阅仍不能冒充候选人或独立评审的人工复核。
- 实际结果、失败尝试及剩余限制见[评估文档](03-evaluation.md)。
