# 需求与成功标准

选题：企业知识问答 Agent。原始题面未提供正式题号，提交时按招聘方实际编号填写。

## 用户与目标

员工查询制度或产品规则，需要可靠答案、可追溯原文和明确的不确定性。资料管理员希望在制度矛盾时暴露问题，而不是系统自行选一个答案。

输入为一个中文问题，以及可选的最多12条user/assistant历史消息。输出包含answer、citations（文档ID、版本日期、片段ID、原文）、gaps、follow_up_question、status。历史只用于理解指代，不作事实来源。

## 范围

- 运行入口选择CLI，Python 3.10+，本地JSON合成知识库。
- 提供文档检索和原文读取两个只读工具。
- 模型每轮选择一个动作，观察工具结果后再决策；可检索、读取、补查、追问或停止。
- 默认10次模型决策、8次工具调用；错误输出修复计入预算；单次模型网络等待默认60秒。
- 无模型时必须显式使用mock；运行标签和记录区分真实模型与规则模拟。
- 不做界面、在线部署、多Agent、生产Runtime、企业权限、实时文档更新或PDF处理。

## 资料约定

`data/documents.json` 是5份完全合成的制度/产品资料，版本日期亦为合成。D01规定30天，D02规定15天，两者未提供范围和替代关系。D03为请假，D04为设备，D05为虚构产品导出规则。

`data/documents-normal.json` 去除D02，用于仅存在D01的正常问答。运行期间知识库复制为固定快照，不读取远程制度。不同case的实际知识库随运行保存，避免用后来改动的资料解释旧答案。

## 必须验收

| 验收点 | 成功标准 | 用例ID |
|---|---|---|
| 明确答案 | 仅D01时回答30天且引用原文 | normal |
| 文档冲突 | 读取D01/D02、补查范围与替代关系、列出双方、不擅自选15天 | conflict |
| 资料外问题 | 不编造宠物保险赔付比例，明确资料不足 | outside |
| 相似改写 | 发票/报账问法仍找到D01并回答30天 | paraphrase |
| 上下文追问 | 将“那需要谁审批”与请假关联，给出两档审批人 | followup |
| 工具失败 | 模型看到错误后调整动作，持续失败明确返回失败 | tool_recovery/tool_failure/read_recovery |
| 内容替换 | D01的30天改45天后回答与引用相应改变 | mutation |
| 上限 | 只有1轮预算时不伪造成功 | step_limit |

至少两条真实执行路径应能表现观察对决策的影响；运行记录必须来自真实执行，不用预写日志充数。所有自动断言只是小样本验收，不能代替对引用语义支持性的逐条审查。
